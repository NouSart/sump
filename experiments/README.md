# experiments · 实验存档

> 这里放**一次性实验**：为了回答某个具体问题而搭的最小验证，不是服务、不是库、不参与构建。

## 规矩

1. **一个实验一个目录**，目录名用「问题」而不是「技术」，例如 `judgeexp`（LLM 判官能否替代规则）。
2. **每个实验自带 `go.mod`**（或等价的独立入口），**不注册进 `go.work`**——根目录 `go build ./...` 不会碰到它。
3. **跑法写在自己的 README 里**，包含：要回答的问题、方法、预注册判据、结果、已知局限。
4. **结果数据落 `data/`**（已忽略入库），仓库里只留语料与代码。
5. **实验不进 CI**。它可能有外网依赖或随机性，不该拖慢主干流水线。
6. **跑完就写完**：结论、负结果、被推翻的前提都要写进去。**没写负结果的实验等于没做**。

## 为什么单独放一层

- 实验代码的生命周期和产品代码不同：前者几周就废，后者要长期维护。混在一起会让人误以为实验是服务。
- 实验的结论应该能被复核。语料 + 臂 + 预注册判据都在同一个目录里，任何人可以重跑。
- 反过来，实验**不得**成为产品依赖——没有任何服务可以 import `experiments/`。

## 新加实验的步骤

```powershell
mkdir experiments/<名字>
# 自己写 go.mod（用 replace 指回 ../../protocol 等），或改用其它语言的独立入口
# 写 README：问题 / 方法 / 预注册判据 / 结果 / 已知局限
```

本目录**不引入** `go.work` 条目，也不要有任何服务 import 它。
