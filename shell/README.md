# shell：命令执行服务

代客执行命令的“代理商”：谁下单执行谁，自己不设判断（判断外包给审批），**受理即回执**，结果另行补报。

```text
run 受理（立即回执 {item_id, window, phase:"queued"}）
  → 审批（接缝；未通过 → 摘出队列 + 补报 rejected，不执行）
  → 执行（**窗口内串行、窗口间并行**；没有全局等待队列）
  → 补报 report_result（approved → done / failed，都带 window）
```

端口默认 `:9701`；模块 `shell/`，入口 `shell/main.go`。

## 窗口：为什么没有排队

**窗口 = 一条串行域。** 同一窗口里的命令按登记顺序一条条跑；不同窗口完全并行、互不认识。

```text
run { command }               → 新开一个窗口（w1），立刻轮到它
run { command, window: "w1" } → 进 w1 的队尾，等前面的跑完
run { command }               → 又开一个窗口（w2），与 w1 并行
```

三条铁律：

1. **不设"全局槽位"**。以前是"并发 8 + FIFO 队列"：第 9 条就得等，等多久取决于别人的命令——
   不可预期、不可解释。现在来几条开几个窗口。
2. **等待只发生在调用方自己指定的窗口里**。那不是"被别人的命令占住"，是**你声明要串行**。
   范围就在这个窗口，前面有几条 `windows` 一查便知。
3. **开不下就明确拒绝**。窗口数超过 `exec.max_windows` → 同步 `{ok:false}`，绝不返回
   "已排队"这种要你干等的回执。

窗口是**调用方可用的句柄**：回执带 `window`，补报也带 `window`；`windows` 动作能查
"哪个窗口在跑什么、谁在等"。所以"这条和那条要串行"由调用方显式表达，服务不猜——
猜错了会把本来能并行的串起来，而串行是这里最不能忍受的代价。

**顺序在受理时固定**：`enroll`（取/建窗口 + 追加队列）在 `actionRun` 里**同步**做完，
再 `go process`。放到后台 goroutine 里定顺序，顺序就取决于调度运气。

审批失败的命令会被**立刻摘出队列**并补报 `rejected`——留着它会卡住同窗口后面所有命令。
空窗口自动回收（队列空且没有在跑的命令）；同名再用等于新建。

## 边界（护栏都在这一个服务里）

| 护栏 | 行为 | 设置键 |
| ---- | ---- | ---- |
| 工作目录 | 必须在**根目录内**（越界、不存在、不可访问 → 同步拒绝；软链先解析再判边界） | `exec.root` |
| 解释器 | 配置远程审批时自动探测 `pwsh` → `powershell`；显式设置优先。自定义 Approver 路径沿用原平台探测顺序 | `exec.shell` |
| 执行超时 | 超时终止**整棵进程树**（Windows：`taskkill /T /F`；Unix：杀进程组），补报 `timed_out` + 退出码 `-1`；**终止失败如实标注**（“进程可能仍在运行”+ 原因原文，不谎称已终止），并设 `WaitDelay=10s` 兜住管道被孙进程占住时的无限等待 | `exec.timeout_ms` |
| 输出上限 | 单流保前 N 字节，附“共多少字节”，**命令照常跑完**（不因截断中断）；上限**每次执行只读一次**（截断与补报文案同一口径，中途改设置不影响本次结果） | `exec.max_output_kb` |
| 并行 | 窗口之间并行、窗口内串行；开满 → 立即拒绝（**不排队**） | `exec.max_windows` |
| 审批 | 见下节；未接入 = 一律未通过。等待时长默认 10 分钟（第二层要等用户在门户裁决，与 approval 的 TTL 对齐） | `approval.service` / `approval.timeout_ms` |

**同步拒绝 vs 补报拒绝**：请求本身不合法（命令为空、工作目录越界）→ 同步 `{ok:false}`；
由不可控因素决定的（审批未通过、队列满、超时、shell 缺失）→ 受理后补报。

## 审批接缝（本副本已接入 approval v1）

审批是 shell 自己的活儿，但“谁裁、按什么协议裁”由审批服务定义。代码里只剩**一个入口 + 一个出口**：

- 生产入口：[`remote_approval.go`](./server/remote_approval.go) 构造执行描述，调用 `approval_request`，核验裁决、摘要与有效期；
- 出口：裁决包进入 `data.approval`，原因、规则与未知结构进入补报 `text`。

`approval.service` 支持服务名；集成启动器设为 `approval` 并显式使用相同 PowerShell。留空仍 `FailClosed`，本次不执行。`Config.Approver` 保留为测试／自定义的显式注入接缝，会绕过远程审批，不应在生产中注入 allow-all。

命令超过 16 KiB、请求超过 64 KiB 或待审批任务达到 64 条，会同步拒绝。审批通过后固定本次的解释器、目录、参数、环境、超时和输出上限，执行前复核；排队超过短期许可则拒绝。**许可期从拿到裁决的时刻起算**（30 秒）——第二层要等用户裁决，按发起时刻算会必然过期。完整范围见 [命令审批说明](../COMMAND-APPROVAL.md)。

## 补报时序（`report_result`）

受理回执的 `phase` 与补报同一词汇（受理 = 第一个阶段 `queued`）；下表是补报用到的阶段：

| phase | 含义 | final |
| ---- | ---- | ---- |
| `approved` | 审批通过，在窗口 X 执行 / 排队（文本里写明） | 否 |
| `rejected` | 未执行（审批未通过 / 窗口开满 / 内部异常） | 是 |
| `done` | 执行结束（含超时：看 `timed_out` / `exit_code` / `error`——超时且终止失败时 `error` 写明原因） | 是 |
| `failed` | 没能跑起来 / 没能跑完（如解释器缺失、进程启动失败） | 是 |

补报发往**发起跳转时的 `from`**（调用方）；调用方离线时记日志并上报投递故障，不做持久队列。只有明确 ignored 的早到补报在 3 秒窗口内重试，网络错误不盲目重发。
`data` 字段带结构化结果（`command` / `work_dir` / `exit_code` / `stdout` / `stderr` / `stdout_bytes` / `stderr_bytes` / `timed_out` / `truncated` / `duration_ms` / `error`）。

## 设置项一览

| 键 | 预设 | 说明 |
| ---- | ---- | ---- |
| `exec.root` | 进程当前目录（`run-local.ps1` 传仓库根） | 工作目录根 |
| `exec.shell` | 空（自动探测） | 指定解释器（需在 PATH 上可解析） |
| `exec.timeout_ms` | `300000` | 单条命令执行超时（≥1000） |
| `exec.max_output_kb` | `256` | 单流输出上限（KB，≥1） |
| `exec.max_windows` | `64` | 同时存在的窗口数上限（≥1） |
| `approval.service` | 空；集成启动器设为 approval | 审批服务名，留空不执行 |
| `approval.timeout_ms` | `60000` | 等审批超时（≥1000；超时按未通过处理） |

## 测试

```powershell
cd shell; go test ./... -count=1
```

- 服务内（`shell/tests/`）：最小中心替身 + 真 shell 实例；**命令用真实子进程执行**——
  覆盖受理回执、fail-closed 拒绝（且确认真的没执行）、审批通过后的 `approved`/`done`、
  工作目录边界、**窗口间并行 / 窗口内串行 / 窗口开满即拒 / 被拒命令不拖住同窗口**、超时终止、输出截断、设置项校验与“改完即生效”。
- 文案分支由包内测试钉住（`shell/server/exec_test.go`）：超时终止与**终止失败**的文本不得互换
  （后者不能宣称“被终止”——这条路径在真实测试里难以稳定触发，字面直接断言）。
- 根 `tests/shell_e2e_test.go`：真进程跨服务——名册里的 `async` 声明、受理回执不等执行、
  补报回到调用方、越界同步拒绝。
- 说明：fail-closed 下真进程 e2e 不会执行任何命令（这是有意的）；执行路径由服务内测试（注入审批实现）覆盖。

## 不做/已定语义（本批）

- 后台任务托管（start / status / logs / kill）、输出有界引用（大输出留句柄按需取）、文件读写工具、
  命令白名单策略、用户审批 UI——前两项见 [DESIGN.md](../DESIGN.md) 的后续批次；策略与 UI 归审批服务。
- **退出即走**：`Ctrl+C`/进程退出不终止在跑的命令（它们成为孤儿进程，仍会跑完）——
  已明确为有意选择（见退出日志里的“在跑 N 条”）；将来要不要“退出杀树”另行决策。
