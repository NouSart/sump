# 智能体怎么跑

> **读者**：要改 reasoner / memory / 记忆与任务语义的人 ｜ **读完能做**：知道一次对话在服务网上怎么流动、状态落在哪里 ｜ **状态**：有效（均已实现，含跨会话共享经验库）｜ **最后校验**：2026-11-01

协议层的约定见 [protocol.md](protocol.md)。本文只讲**运行时语义**：工具异步、会话记录、任务、经验网、复盘。

## 1. 工具异步模型（reasoner 侧）

- **派发即回执**：LLM 发起工具调用后，立即为每个调用记一条「已受理」`tool` 回执（占住 OpenAI 协议要求的 `tool_calls` 配对位），执行转入后台（单次超时默认 60s）。
- **结果注入**：工具完成后，结果作为 `[工具结果] <名>（job=<id>）` 消息（role=user）注入黑板；
  - 通知模式 = 设置项 **`tool.notify_mode`**：`each`（默认，逐条唤醒）/ `batch`（攒批唤醒，等最后一个结果）；设置中心可覆盖（reasoner 启动时拉取生效，启动值 `-tool-notify`）。
- **内置工具 `wait`**：阻塞等待本会话全部工具任务完成（上限 5 分钟）；结果未到齐、不能收尾时使用。
- **收尾门禁**：最终答复被接受的前提 = 在跑工具已到齐、且任务已被判定（见 §3）。
- **黑板（任务窗口）**：进行中任务的最新消息链 + 在跑工具表存于 reasoner 进程内（唯一副本）；任务被同会话新消息取代时旧任务关闭、在跑结果丢弃（日志可见）。窗口 = 任务在跑期，交付即释放——不落盘、不跨重启（这是独立性约束里唯一的例外）。
- **轮次衔接**：`step`（自跳）payload 只带 `conversation_id`（上下文在黑板里）；轮次由事件驱动（派发 / 结果注入 / 等待 / 收尾门禁），不驻留循环。
- **补报到达时**（`report_result`，见 [protocol.md §6](protocol.md)）：任务在跑 → 注入黑板并唤醒；任务已收尾 → 以补报开一轮「补报轮」（结果不丢，模型据此给 boss 补一句，boss 为空则记日志丢弃）。补报不进入任务的「在跑工具」表——模型的收尾不该被一条长命令扣住。

## 2. 会话记录：对话 + 过程轨迹

记忆服务（memory）保管的不只是「用户说了什么 / 智能体答了什么」：

| `kind` | 内容 | 谁写 |
| --- | --- | --- |
| `user` / `assistant` | 对话本身 | reasoner（链入口 / 交付成功后） |
| `reasoning` | 模型这一轮的思考（`reasoning_content`） | reasoner（每轮有思考就记一条） |
| `tool_call` | 工具调用（shell 类工具直接给出 `command`） | reasoner（派发时，**执行前**落库） |
| `tool_result` | 工具输出（异步工具取**终态补报**的文本，不是「已排队」回执） | reasoner（结果入账时） |

- **只有 `user` / `assistant` 进 LLM 上下文**（`recall` 的 `Recent` 过滤）：思考回灌纯浪费，工具结果缺少配对的 `tool_calls` 会被上游直接拒。轨迹是**给人看**的。
- **`seq` 由写入方给**（微秒时间戳，跨重启仍递增）：`Fire` 是 goroutine，落地顺序不保证，`seq` 保证「命令在输出之前」这种真实先后；门户也用它去重。**不能超过 2^53**——它要经 JSON 到浏览器，纳秒级会被 JS 的 number 抹平，相邻记录可能撞成同一个数。
- 单条上限 8000 字符，超出标 `meta.truncated = true` + `full_chars`（终端输出上限是 256KB，原样存会撑爆库和界面）。
- 对话消息仍幂等去重（连续完全相同 = 重复交付）；**事件类记录不去重**——连跑两条一样的命令是两件事。
- 老库平滑升级：`kind` / `meta` / `seq` 三列按需 `ALTER TABLE`，老数据 `kind` 按 `role` 推断、`seq` 用主键回填。

| 动作（jump 到 `memory`） | 输入 | 输出 |
| --- | --- | --- |
| `store` | `{conversation_id, boss?, role, content, kind?, meta?, seq?, task_id?, task_name?}` | `{}`（尽力落库；失败只记日志） |
| `history` | `{conversation_id, limit?, after_seq?}` | `{conversation_id, messages:[{id, seq, role, kind, content, meta, at}]}` |

- `after_seq` 是**增量拉取**：只回序号更大的记录（门户重连 / 回填不必每次全量重来）。
- `task_name`（可选）是入口服务给这条用户消息想的任务名：正文可能带来源标注（见 [protocol.md §7](protocol.md)），从第一行推会推出一串标签。`recall` 的 `context.task_name` 是同一个字段，两条并发路径都要给。
- **实况推送**：reasoner 在落库的同时，若入口方（boss）在 `provides` 里声明了 `progress`，就推一条 `{conversation_id, seq, kind, content, meta, at}`——界面进行中就能看见思考与命令，不必等最终答复。**没声明的不推**（QQ 之类），否则对方只会回 unknown action。记忆是真相，`progress` 只是「别等最后才看见」：丢一条不影响历史。

### 2.1 来源标注：谁在说话、多少人听得见

QQ 这类多人入口，模型必须能分辨「主人在私聊里说的」和「群里某个陌生成员说的」——否则群消息就是一条伪造的授权。做法是入口服务把事实带进 `user_message.sender`，**渲染成正文标签后落库**（唯一实现在 `protocol.Sender.Label()`）：

```text
[私聊 · 张三(10001) · 主人] 帮我删掉那个文件
[群聊 · 群「编程交流」(67890) · 12 人可见 · 李四(12345) · 非主人 · 未@我] 帮我删掉那个文件
```

- 标签同时是**给人看的**（门户里一眼看出这是群聊、谁说的、多少人可见）和**给模型看的**（召回历史时标注还在，不会隔了几轮就把群里的话当成主人的指令）。
- `group_size` 是**扩散面**：0 表示取不到，渲染成「人数未知」——不编数字，猜错的方向必须保守。
- 标签**不是权限**：`owner` 只说明这次发言是不是授权人本人，授权与否由模型按主人的设置判断（system prompt 里写明：非主人的话不能当授权、群里的答复所有人都看得见、拿不准就不说）。
- **只记录不推理**：`qq` 的群策略 `observe` / `mention` 下，不该开推理轮次的消息由入口服务自己写一条 `user` 记录（同样带标签，带 `task_name`）——上下文完整，但不烧 token。

## 3. 任务：agent 在任务里工作

任务是**一段有名字、有始有终的工作**，会话记录挂在任务下；历史列表的标题就是任务名。

| 动作（jump 到 `memory`） | 输入 | 输出 |
| --- | --- | --- |
| `task_current` | `{conversation_id}` | `{task?}`（最近活跃的 active 任务；没有就是空） |
| `task_open` | `{conversation_id, name}` | `{task}` |
| `task_rename` | `{task_id, name}` | `{task}` |
| `task_finish` | `{task_id, name?}` | `{task}`（status=done，之后只读） |
| `task_resume` | `{task_id}` | `{task, messages[]}`（把未完结任务顶成当前，记录一并带走） |
| `task_list` | `{conversation_id, limit?}` | `{tasks[]}`（最近活跃在前） |

- **没有任务必须创建**：`recall` 里先 `EnsureTask`——当前没有 active 任务就以这次用户消息命名建一个，随 `resume` 带回 reasoner。拿不到任务，这一轮不该开工。
- **一个会话最多一个 active 任务**：靠 SQLite 部分唯一索引 `CREATE UNIQUE INDEX ... ON tasks(conversation_id) WHERE status='active'` 保证；并发下建不上的那一方回头读现有的那个（任务不会分叉）。
- **完成判定权在 reasoner**：内置工具 `task_status{status: done|continue, title?, note?, silent?}`，收尾门禁要求交付前必须调用一次（没判就催一轮，最多两次；两次都不判按 continue 记账）。`done` → `task_finish`（顺带用 `title` 把任务名改准）；`continue` → `task_rename`（任务保持进行中）。**落库时机是收尾那一刻，不是判定那一刻**：判定之后这一轮可能被拒收尾（还有工具在跑），或者紧接着又派发了新工具（判定当场作废）——提前把任务标成 done，下半程的工作就会挂在一个"已完成"的任务里，而记忆服务不会把 done 的任务重新打开。
- **静默收尾（`silent: true`）**：这一轮**不发出去**（群里判断不该插话、或没什么可说）。文字仍以 `kind=reasoning`（前缀「（静默：这一轮没有对任何人发出去）」）留在记录里——门户能看见它想过什么，人才能判断静默得对不对。静默不粘性：每次判定重设，派发新工具时与「已判定」一起作废。它只影响「说不说」，不影响任务是否完结。
- **完结 = 不再续**：已完结任务不接受继续（`task_resume` 明确拒绝）。但它的记录还在会话里：门户按**任务分节**连续展示整段会话，侧栏是「会话 → 任务」的目录，点任务只是跳到那一段（不切换视图、不过滤）。**未完结 = 可恢复**：记录都还在（`task_id` 一列），点开就回到那一段继续。
- **记录归属**：`store` 带 `task_id`；没带时——`user` 记录会触发 `EnsureTask`，其他记录（答复 / 轨迹）挂到**最近一个任务**上，绝不悬空。**连续两条 role+content 完全相同的对话消息只留一条**（防重复交付）：同一个人把同一句话原样再发一遍会被吞掉，事件类记录（思考 / 工具）不去重。
- **LLM 上下文按任务取**：`recall` 只取当前任务的对话消息（`Recent(..., taskID)`），换任务即换上下文。
- **老数据**：迁移时每个会话补一个已完结的「历史记录」任务，旧消息全部挂上去（不丢历史）。
- 任务现在**只存事实**（名字 / 状态 / 归属），不解释语义。要独立成服务时，把 `tasks` 表与这六个动作整体搬走即可。

### 会话本身也是一行（`conversations`）

任务是「会话里的一段工作」，**会话**是比它更外一层的东西：能起名字、能分入口、能归档。没有这张表，历史记录页只能靠 `GROUP BY conversation_id` 现凑——起不了名，多会话也无从谈起。

| 动作（jump 到 `memory`） | 输入 | 输出 |
| --- | --- | --- |
| `conversation_list` | `{limit?, include_archived?}` | `{conversations:[{id, title, entry, status, created_at, updated_at}]}` |
| `conversation_open` | `{id, title?, entry?}`（幂等建行；只在空时填） | `{conversation}` |
| `conversation_rename` | `{id, title}`（空串 = 清掉名字） | `{conversation}` |

- **只存元信息**：`title` / `entry` / `status` / 两个时间。消息数、任务数、最后一句说什么全部现算——冗余字段迟早和真相打架。
- **写入即建行**：`store` 落库成功后自动 upsert（`Record` 内部），谁都不用显式建会话。只有落库**成功**才推 `updated_at`，否则列表里会出现「刚活跃过」的空会话。
- **`entry` 取 boss 不取 `env.From`**：记录是 reasoner 代写的，真正「从哪扇门进来」的是它替谁办事（`frontend` / `qq`）。只在空时填，后来的不覆盖——第一次从哪进来就是哪。
- **`title` 为空是真的空**，不造假名字：界面自己回退一个占位。起名是件明确的事（`conversation_rename`），不靠「顺带」。**入口服务例外**：它第一次见到会话时就知道这是谁（qq 会写「QQ 私聊 · 昵称」/「QQ 群「群名」」），用 `conversation_open` 把名字交上来；只在原来为空时填，用户改过的名字不会被顶掉。取不到名字（比如群资料拿不到）就不起名，宁可让界面回退占位。
- **老库回填**：从 `messages` / `tasks` 里已有的 `conversation_id` 聚合出会话行（首末时间为界），升级后历史记录页立刻能用。
- 这几个动作都**不声明 `tool:true`**（在 `provides` 里可见、可直连，但不给模型当工具）：界面导航不是模型该自己做的决策。

## 4. 经验网：把做过的事变成能「抓线头」的经验

会话记录是**流水**（按时间、给人看）；经验网是**联想**（按语义、给模型用）。两者永不混用：历史记录页只读流水的表，经验网只给 recall 与 `dig`。

实现是一个**独立 Go 包** `memory/memnet`：零依赖本仓库其他包、只吃一个 `*sql.DB`，表与阈值都是它自己的——将来整块搬走即成独立仓库 / 独立服务。细则见 [memory/memnet/README.md](../../memory/memnet/README.md)。

| 动作（jump 到 `memory`） | 输入 | 输出 |
| --- | --- | --- |
| `note` | `{content, conversation_id?, task_id?, durability?}` | `{id, node_ids, duplicate, skipped}` |
| `dig`（`tool: true`） | `{entry_id?, node_id?, limit?}` | `{notes[], total}` |
| `lineheads` | `{query, limit?}` | `{heads:[{node_id, text, count, score, task_id, members}]}` |
| `prune` | `{}` | `{entries, links}` |

- **一条经验 = 一句话**（总结 / 用了什么技术 / 踩了什么坑，各是一条），带 `task_id` 指回当时的完整存档。
- **树只有一层**：偏好 / 事实 / 做法 / 坑 / 取舍五个大类，把种子句的向量当定义，**永不随成员重算**（否则五个大类会彼此趋同）。第二层不落库——持久化二级枝会被「成员均值」带跑（质心融化，实测可见）。
- **网在归属上**：一条经验可同时挂多个大类（`mem_links`，带粗细），`MaxLinks` 控制上限。
- **线头是派生的**：`recall` 里先全库按相关度捞，再把候选**现算**成簇，每簇一行 `[N 条 · 分数] 代表句（id=…，来自 task-…）`。糊了下次换 query 重新聚，不会永久长歪。
- **比较前必减语料均值**：短句向量各向异性，原始余弦的同义 / 无关几乎重叠（间隔 +0.068），中心化后 +0.216——这是阈值能用的前提。均值是派生缓存，不进库。
- **遗忘曲线只作用在条目上**：`S = S₀ × growth^(hits-1)`、`R = exp(-Δt/S)`，排序用 `cos × R`。复现靠「又被观察到」，**不靠被召回**（否则形成回音室）。`core` 不衰减，`transient` 不进网。
- **剪枝是软的**：`R` 跌破线只标 `pruned`（不删行、不删向量、留着强度），重新遇到能复活。
- **整理时机不做死在服务里**：`note` 是纯动作，谁调都行（收尾后 / 定时 / 门户手动）。

## 5. 复盘与单步推理：模型调用只有一个出口

**所有非任务型的模型调用都走 llm 服务**（reasoner 本身就是那个服务）：别的服务不配自己的 LLM 客户端、不散落 Key，一律 jump 到 `think`。

| 动作（jump 到 `reasoner`） | 输入 | 输出 |
| --- | --- | --- |
| `think` | `{prompt, system?, model?, max_tokens?}` | `{text}` |

- **一次补全，来去干净**：不带工具、不开任务、不进黑板、不写记忆。与任务链零交集。
- **不声明 `tool:true`**：不给 LLM「让自己再想一次」的按钮——那是无限自我循环的起点。（动作本身在 `provides` 里，别的服务可以直连。）
- `model` 非空即覆盖默认模型（「最小不思考」= 指一个非推理模型）；`max_tokens` 硬夹到 4096；提示词超 20 万字符直接拒（一个误拼的循环能把账单打飞）。

**复盘（交付后写经验）**：任务交付 boss **之后**在后台跑一次，把这一段做过的事变成经验网的条目（`note`）。老板已经拿到答复，复盘成败都不影响他。

- **何时**：交付成功且任务没被新消息取代（被打断的半截工作不是可复用经验，是噪音）。
- **谁写**：llm 服务自己（与 `think` 同一条路，只是预置了提示词）。
- **写什么**：做法 / 坑 / 事实 / 偏好 / 取舍，一条一句话、独立可读；**允许 0 条**（宁缺勿滥），上限 3 条。
- **耐用度不由模型定**：`kind=偏好` → `core`（不衰减），其余 `durable`。让模型自己挑，它会全标 core，网就再也不遗忘了。
- **不设「太短就不复盘」的门槛**：最短的最值钱——「以后都用中文回复」只有十个字，却必须记住。长度门槛会精准筛掉这类经验；宁可让模型看一眼再自己说「没有值得记的」。
- **开关**：设置项 `reflect.on`（启动值 `-reflect`，默认开；关掉后已写进网的不会删）。

**长任务怎么塞进一次复盘请求**（借用 opencode 与 codex 的同一套形状，2026-10 版）：

1. 不把原始消息链丢给总结模型，先序列化成带角色前缀的流水（`[用户]` / `[助手]` / `[工具调用]` / `[工具输出]`）。
2. **工具输出是体积来源，先砍**：单条截到 1250 字（opencode `TOOL_OUTPUT_MAX_CHARS = 1_250`）。
3. **最近的逐字保留，早的骨架化**：最近 8k token 原样留（opencode 现在默认 15k，它要能让下一个人接着干，我们只要看清最近这一段）；更早的用户消息留 500 字（用户说的话是需求本身），助手留 300 字，工具输出留 200 字——**不能全丢**，报错原文是「坑」的唯一证据。
4. **切分点对齐到轮次**（opencode 的 `recentStart`）：一轮要么整轮逐字、要么整轮骨架化，绝不出现「工具调用留着、它的输出被丢了」这种半截状态。
5. **硬上限 40k token**：还超就从最老的丢，并在开头写明 `[更早的 N 条记录已省略]`——不假装看到了全部。

与两家的差别：他们对超出的部分**再调一次模型做摘要**（opencode 现在还有锚定更新 `buildPrompt(update)`、`SHRINK_STEPS` 在被「太长」拒绝后按 0.7/0.5/0.35 缩预算、用 provider 回报的 usage 当锚点的 measured+estimated 估算），我们暂时只做「截断 + 骨架化」，一次复盘只花一次模型调用。等真有任务长到 40k token 都装不下，再补「二次摘要」那一层。

## 6. 跨会话：共享经验库

一个问题必须答清楚：**两个会话之间到底共享什么？**

| 层 | 内容 | 谁看得见 | 落点 |
| --- | --- | --- | --- |
| 会话私有 | 对话、工具调用与输出、任务与文件 | 只有当事会话 | `data/memory.db` |
| 用户共享 | 偏好 / 事实（`remember`）、一句话经验（经验网）、会话目录 | 所有会话 | `data/experience.db` |

判据很简单：**能进共享库的只有提炼物**。摘要里没有原话、没有路径、没有命令、没有账号——发布载荷里根本没有这些字段，想加得先改协议。

### 6.1 会话目录：别的会话在干「什么」

| 动作（jump 到 `memory`） | 输入 | 输出 |
| --- | --- | --- |
| `publish_session` | `{conversation_id, task_id, title?, goal?, outcome?, capabilities?, private?}` | `{published, private}`（复盘调用；**不暴露给模型**） |
| `shared_sessions` | `{limit?, exclude?, query?}` | `{sessions:[{entry, title, tasks:[{title, goal, outcome, capabilities, created_at}]}]}` |
| `shared_forget` | `{session_id?, task_id?}` | `{sessions, tasks}`（维护用；不暴露给模型） |

- **写入时机**：复盘那一次模型调用顺带产出 `digest{goal, outcome, private}`——**零额外调用**。关掉 `reflect.on` 就没有摘要（目录会停在最后一条）。
- **能力族是统计出来的**：`capabilities` 由 reasoner 从本轮 `tool_call` 的 `服务__动作` 前缀确定性统计，不让模型措辞（它会把没用过的工具也写上）。
- **`private` 由模型标、用户可关**：标记的任务只写经验、不进目录；整机开关是 `share.on`。
- **每个会话最多留 3 条任务摘要**：目录是"现在在干什么"，不是归档。
- **脱敏是第二道**：提示词明确禁止写路径 / 命令 / 账号，库侧再兜一层（去链接、路径、邮箱、密钥形状、手机号，压平换行）。

### 6.2 读：仍然由记忆服务组装

`recall` 组装的记忆块多了最后一节：

```
（其他会话）
这些是别的会话**在做什么**的摘要；你看不到它们的对话、工具输出与文件。
- 门户「配色调整」：在改门户的时间主题；还没定稿（2 小时前；用到 shell/files）
```

- 预算：`share.sessions_limit`（默认 5，0 = 不带）+ `share.digest_chars`（默认 120）——目录是背景信息，不该挤占对话。
- 共享库读失败 = **本节省略**，不阻断这一轮（与经验网失败的处理一致）。
- 想多看一眼就调 `shared_sessions` 工具；`dig` 只能下探到共享经验，**没有路径**能拿到别的会话的原文。
- 排除自己是硬规则：目录永远不含当前会话。

### 6.3 门户侧（不在本 PR）

门户是"一个用户 + 多个会话"，它的界面（会话树 / 新建 / 改名 / 归档 / 其它入口的只读浏览）需要门户那一侧的实现，随门户分支落地；协议侧的 conversation_open / conversation_archive 与"读宽写窄"的边界已经在 memory 里备好。
