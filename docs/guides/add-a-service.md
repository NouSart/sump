# 写一个服务

> **读者**：要给 SUMP 加一个新能力（= 一个新服务）的人，不限语言 ｜ **读完能做**：写出一个能被中心发现、被模型调用、被测试覆盖的服务 ｜ **最后校验**：2026-10-30

协议契约（信封、消息类型、链机制）见 [../concepts/protocol.md](../concepts/protocol.md)。

## 1. 最短路径

1. 建目录 `<服务名>/`，`main.go`（或任意语言入口）+ `tests/`
2. 从启动参数拿三要素：`-name` / `-addr` / `-center`
3. 向中心 `register`，名片里写清 `provides` 与 `settings`
4. 收 `jump` → 按 `action` 分派 → 回 `response`
5. 每 15s 发 `heartbeat`；退出前发 `status="bye"`
6. 断线指数退避重连 + 重新注册
7. 给每个动作写测试（含错误路径）
8. 在 `go.work`（Go）或启动脚本里登记
9. 只暴露能力类动作（`tool: true`），管理 / 调试动作不要暴露
10. 需要长耗时 → 用 `async: true` + `report_result` 补报，不要让调用方等

Go 服务直接用 `service/` 骨架（注册 / 心跳 / 名册 / 重连 / 告别 / 设置接收都现成），只写业务动作。**其他语言照此实现即可**：`protocol/` 与 `service/` 是 Go 侧的便利库，不是准入条件。

## 2. 名片：`provides` 与 `settings`

```jsonc
{
  "name": "images",
  "addr": "ws://127.0.0.1:9401/ws",
  "description": "图片服务：保存图片（URL/base64），按需转 base64 发回调用方",
  "provides": [                                  // 我对外提供哪些动作（"tool": true 才作为 LLM 工具暴露；"async": true = 受理即回执）
    { "action": "save",  "input": "{url} 或 {data(base64), mime}", "output": "{id, mime, size}" },
    { "action": "fetch", "input": "{id}", "output": "{id, mime, data(base64), size}" }
  ],
  "settings": [                                  // 我可被设置哪些项（预设值 = 本服务启动引导值；只声明真正消费的项）
    { "key": "max_mb", "default": "32",                                      // 普通项：值由中心保管
      "label": "单张图片大小上限", "kind": "number", "unit": "MB" },          // 人话元数据（可选）
    { "key": "llm.key", "secret": true, "set": false },                      // 秘密项：值由服务自己持有
    { "key": "addr", "default": "127.0.0.1:9101", "readonly": true }         // 只读项：启动参数带起来的
  ]
}
```

- `provides[].input/output` 是**给人看的宽松描述**，不是 JSON Schema。精确字段形状由协议包里的载荷类型定义（`protocol/payloads.go`）。
- 名片字段名（`action` / `input` / `output` / `tool` / `async` / `batchable`）跨语言一致，见 [命名基线](../concepts/protocol.md)。

### 2.1 设置项的人话元数据（全部可选）

服务不给，面板就退回「键名 + 文本框」：

| 字段 | 用途 |
| --- | --- |
| `label` | 中文名。面板优先取语言包 `setting.<service>.<key>.label`，再回落这里 |
| `hint` | 一句话说明：改它会发生什么、留空意味着什么 |
| `kind` | 控件类型：`bool` / `enum` / `number` / `text` / `textarea` / `service` / `optional-service`（缺省 `text`） |
| `options` | `enum` 的候选**原值**；标签走语言包 `setting.<service>.<key>.opt.<value>`，缺了就显示原值 |
| `unit` | `number` 的单位**符号**：`ms` / `MB` / `KB` / `chars` / `count`。面板翻成人话（`300000 ms → ≈ 5 分钟`）；服务收到的仍是原始数值 |

`service` 表示值是一个服务名：面板从名册里列候选，但**名册只是候选，校验权仍在服务**（名册里没有的名字照样提交，服务自己拒）。`optional-service` 表示该项可以「没有」（清空 = 关闭这项能力），面板画成「开关 + 选择」。

## 3. 设置中心提供的动作

| 动作（jump 到 `settings-center`） | 输入 | 输出 |
| --- | --- | --- |
| `list_settings` | `{service?}`（可选过滤） | `{services:[{service, settings:[{key,value,default,overridden,secret?,readonly?,set?}]}]}` |
| `set_setting` | `{service, key, value}` | 被改动服务的设置（同上结构） |
| `reset_setting` | `{service, key}` | 同上（回落预设值；秘密项 = 让服务清空） |
| `report` | `{kind?, message}` | `{status:"ok"}`（中心记日志并交给消费挂点） |

- 生效值 = **覆盖值 ?? 服务声明的预设值**；覆盖值落盘于设置中心（`data/settings.json`）。
- 校验两级：中心只校验「服务已注册、设置项已被声明」；**值是否合法由服务自己校验**——`configure` 被服务拒绝即保持旧值（中心把拒绝理由记入结果事件）。
- **下发（注册即对齐 + 变更单键）**：中心在 `register` 响应发出后**异步**（不阻塞注册、不等待送达）把该服务的普通项生效值逐键以 `configure` 下发（有界重试 +0.5s、+2s；服务明确拒绝不重试）；`set_setting` / `reset_setting` 成功后单键下发。**受理回执只表示「已落盘受理」**，送达结果（含失败原因）以 `settings` 事件广播：`{cause, service, results:[{key, value?, ok, error?}]}`（cause = `register` / `set_setting` / `reset_setting`）——面板据此自动刷新与提示。
- **服务侧接收（骨架通用）**：Go 骨架提供 `HandleSetting(键, 预设, 校验+应用回调)`——声明进名片、统一承接 `configure`、注册成功后**异步拉取一次**作兜底（只应用覆盖项；与下发幂等）；另暴露 `RefreshSettings()` 手动拉取。预设值由**服务自己决定**；非 Go 服务照此实现。
- **离线一致性**：服务离线期间的变更**不排队补发**——其下次注册时全量对齐（幂等收敛）。

## 4. 三类设置项

- **普通项**：值由中心保管（覆盖值落盘中心），注册时全量对齐下发。
- **秘密项**（`secret: true`，如 API key、token）：值**不进中心**——中心不落盘、不回显（`list_settings` 里 `value` 恒空），只在面板提交那一次把值**转发**给服务；由**用它的服务自己**持久化（骨架 `HandleSecret` + `Config.SecretFile`，`Start()` 时自己加载并应用）。名片里 `set` 只说明「服务侧当前有没有值」（面板据此显示「已设置」，值本身永不上线）；**注册对齐不含秘密项**；`reset_setting` = 推空值过去让服务自己清。一句话：**谁消费谁持有**。
- **派生状态**：需要根据秘密生成身份等派生状态时，Go 服务用 `HandleSecretWithCommit(键, 校验, 发布)`——校验不修改运行时状态；保存成功并更新生效值后才发布；保存失败不发布。启动加载也经过校验与发布，但不回写文件。发布回调只做不会失败的本地状态切换，可释放旧连接，不发起或等待网络请求，也不重入设置变更。
- **识别成功轮换**：用 `SettingSnapshot` 同时读取生效值与进程内版本；成功改变值才推进版本，保存失败、重复保存当前值均不推进。版本按键独立，不进入消息协议、不跨重启使用。
- **只读项**（`readonly: true`，含 `-name` / `-addr` / `-center` 三要素，以及各服务的存储身份 `db` / `dir`、中心的 `settings`、门户的 `web`）：面板只读展示（值 = 启动值，放在 `default`），`set_setting` / `reset_setting` 一律明确拒绝——**改它要重启**（重启按钮另做）。**路径类参数默认只做只读**：运行中换库 / 换目录等于让在途读写换个落点，不做。
- **面板语义**：秘密项显示「已设置 / 未设置」+ 覆盖（密码框）+ 清空；只读项显示启动值、无修改入口。
- **安全边界（说清楚，不假装）**：秘密文件是**明文**（本机单用户场景，等同 `.env`；写时目录 0700、文件 0600、原子替换）；面板提交那一次的值走的是中心 ↔ 服务之间既有的本机 WS 通道（与其它协议流量同级）。中心侧全程不留值：不落盘、不回显、日志掩码、`settings` 事件不带值。
- 不做 `env:` 之类二级引用写法：**不叠机制**，要换值就在面板覆盖一次。

## 5. 服务自报：服务侧的值自己变了

控制方向只有一条（中心 → 服务 `configure`）；反方向的 `report_setting` **只报事实**：

| 动作（jump 到 `settings-center`） | 输入 | 输出 |
| --- | --- | --- |
| `report_setting` | `{service, key, value, set?, seq}` | 被改动服务的设置（同上结构） |

- 服务侧的值因自身原因变化时（自适应 / 规范化 / 程序内部改写），服务主动报一条——骨架 API `AnnounceSetting(键)`：异步发出（**不阻塞**服务）、失败不排队（下次注册名片对齐收敛）。
- 中心**不改**自己手里的覆盖值，只把这条记进「服务侧实际值」那一列：面板同时看得见**中心口径的生效值**（`value`）与**服务侧实际值**（`actual`），不一致时给一个「服务侧已变」标记。
- **秘密项 `value` 恒空**：只回 `set`（服务侧有没有值），值永远不上线。
- `seq` 服务内单调递增：中心丢弃比已记下更小的旧报（回传与补报的到达顺序都不保证）。
- 服务侧实际值是**运行时态**：不落盘（中心重启后为空，等服务下次回传或注册对齐）。

## 6. 测试要求

- 服务自带 `tests/`：起真实服务 + 真实 WS，覆盖自己的动作（含错误路径）。
- 根 `tests/`：跨服务**真进程**端到端（新增链路时补一条）。
- 测试**不得依赖外网**：用假 LLM（OpenAI 兼容替身）/ 假对端；真模型只在显式开关下跑冒烟。
- 测试里构造消息建议**手写字段**（当「只读规范的第三方」），而不是复用生产结构体——这样契约漂移会立刻被测试抓住。

## 7. 别做的事

- 管理 / 调试类动作（改配置、清库、发号施令型代理）暴露给 LLM。
- 直接读写别的服务的库表或目录。
- 让调用方等你完成长任务（用 `async` + `report_result`）。
- 新增设置同步通道（设置只走服务 ↔ 中心）。
- 为了快把能力写死进别的服务的流程里——写死一次，就抽不出来一次。
